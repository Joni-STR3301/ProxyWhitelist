# Proxy whitelist — легковесный HTTPS‑прокси для белого списка сайтов

Это простое Python‑приложение‑прокси, которое ограничивает доступ к интернету **только к сайтам из белого списка**. Всё, чего нет в списке, автоматически блокируется с ответом `403 Forbidden`.

## Для кого это и зачем?

- **Школы, библиотеки, коворкинги** — где нужно контролировать доступ к интернету, но нет денег или времени на дорогие корпоративные решения.
- **Локальная сеть без сервера** — достаточно одного ПК или ноутбука администратора в сети.
- **Люди, которые не хотят городить “индустриальные” решения** — никаких LDAP, DLP, специальных шлюзов. Всё — через один `mitmdump` + простой GUI‑интерфейс.

### Что умеет приложение

- Разрешает доступ **только к доменам из `whitelist.txt`** (всё остальное — блокируется).
- Показывает “живую” консоль с логами: кто с какого IP куда пытается зайти, `ALLOWED` или `BLOCKED`.
- Позволяет управлять списком через окно: добавлять/удалять домены, обновлять список.

---

## Как всё это работает (кратко)

- На одном ПК в сети запускается приложение `Proxy whitelist` → оно запускает `mitmdump` как прокси‑сервер (`localhost:8080` по умолчанию).
- Все устройства в сети (ноутбуки, ПК) настраиваются идти **через этот прокси** (HTTP + HTTPS).
- HTTPS‑трафик проксится через `mitmproxy`, поэтому **нужно поставить сертификат `mitmproxy` как доверенный** — без этого ни один HTTPS‑сайт работать не будет.
- В `whitelist.txt` лежит список разрешённых доменов; приложение автоматически читает его, фильтрует трафик и логирует всё в `access.log`.

---

## Структура репозитория

- `proxy_whitelist.py` — основное приложение на Python + PyQt5.
- `whitelist.txt` — **готовый белый список доменов** (будет пополняться и поддерживаться в репе).
- `access.log` — логи доступа.
- Дополнительно можно добавить `requirements.txt` с зависимостями Python, если захочется.

## Установка и настройка на сервере

### 1. Установка `mitmproxy`

Если `pip install mitmproxy` не работает, делайте так:

1. Откройте в браузере официальную страницу `mitmproxy`:  
   [https://www.mitmproxy.org/downloads/](https://www.mitmproxy.org/downloads/)
2. Скачайте установщик под вашу ОС (Windows `.exe`, macOS `.pkg`, Linux `.tar.gz`).
3. Установите `mitmproxy` как обычную программу.
4. Убедитесь, что в терминале/консоли работает:

```bash
mitmdump --version
```

Если команда отвечает версией — `mitmproxy` установлен.

---

### 2. Установка Python‑зависимостей

В любом удобном месте (не обязательно в одной папке с приложением) выполните:

```bash
pip install PyQt5
```

(или `pip3`, если у вас несколько версий Python).

---

### 3. Запуск приложения `Proxy whitelist`

1. Скопируйте на сервер:
   - `whitelist_manager.py`
   - `whitelist.txt`
   - `access.log` (можно создать пустой `touch access.log` / `type nul > access.log`)

2. В терминале/консоли, **в папке с `proxy_whitelist.py`**, выполните:

```bash
python proxy_whitelist.py
```

Откроется окно:

[Здесь можно вставить скриншот окна приложения]

Если в строке статуса появится сообщение о том, что прокси запущен — всё работает.

## Настройка устройств в сети

Все устройства — ноутбуки и ПК, **на любой ОС**, — должны идти через этот прокси.

### 1. Получение IP сервера

На сервере:

- Windows: `ipconfig` → смотрите `IPv4 Address` (например, `192.168.1.100`).
- Linux/macOS: `ifconfig` / `ip addr show` → смотрите `inet` в нужном интерфейсе.

Запомните этот IP: он будет **адресом прокси** для всех устройств.

---

### 2. Установка прокси на устройствах

На каждом ПК/ноутбуке:

- Перейдите в настройки Wi‑Fi / Ethernet.
- Включите ручной прокси:
  - `HTTP Proxy` → `192.168.1.100:8080`
  - `HTTPS Proxy` → `192.168.1.100:8080`

Пример для Windows:

- `Settings` → `Network & Internet` → `Proxy` → `Manual proxy setup` → IP + порт.

Пример для macOS/Linux (через браузер или системные настройки) — аналогично.

---

### 3. Установка сертификата `mitmproxy` (обязательно!)

**Без этого сертификата ни один HTTPS‑сайт работать не будет.**

1. В браузере на устройстве перейдите:

```text
http://mitm.it
```

2. Выберите свою платформу (Windows, Linux, macOS).
3. Скачайте сертификат.
4. Установите его в системное хранилище:

- Windows: через `certmgr.msc` → `Trusted Root Certification Authorities`.
- macOS: через `Keychain Access` → добавить сертификат и поставить ему **“Always Trust”** для SSL/TLS.
- Linux: обычно через общий storage сертификатов системы (зависит от дистрибутива).

После этого HTTPS‑сайты будут открываться, а `whitelist.txt` применяться к `https://`‑ресурсам.

## Как пользоваться GUI‑панелью

Когда приложение запущено:

### Левая часть — логи

- В `QTextEdit` показываются логи в формате:

```text
[2026-04-30 13:00:00] [ALLOWED] [192.168.1.10] -> https://ya.ru
[2026-04-30 13:00:01] [BLOCKED] [192.168.1.10] -> https://bad-site.com
```

- `ALLOWED` — зелёный; `BLOCKED` — красный; IP и URL — белый.

### Правая часть — управление списком

- В поле `Домен:` введите домен (без `http://`, `https://`, `www.`):  
  например `ya.ru`.
- `Добавить` — домен сохраняется в `whitelist.txt` и появляется в списке.
- `Удалить` — выбранные домены удаляются из списка и из файла.
- `Обновить` — перечитывает `whitelist.txt` и актуализирует список.

Строка статуса покажет:

- если `whitelist.txt` пустой — все сайты разрешены;
- если есть домены — блокировка всего остального.

---

## Формат `whitelist.txt`

Файл содержит **домены**, по одному на строку:

```text
google.com
google.ru
ya.ru
yandex.ru
vk.com
mail.ru
pikabu.ru
```

Правила:

- `ya.ru` автоматически разрешает `ya.ru`, `news.yandex.ru`, `disk.yandex.ru` и т.п.
- `google.com` → `maps.google.com`, `drive.google.com`.

HTTPS‑сайты **без установленного сертификата `mitmproxy` работать не будут** — это не ошибка, а особенность HTTPS‑фильтрации.

---

## Почему это хорошо для учреждений

- Не нужно дорогое железо или сервер;

- Не нужно специальное ПО (DLP, корпоративный шлюз);

- Масштабируется на сеть из 10–100 устройств;

- Логи доступа и белый список — в одном месте, простым текстом и оконным интерфейсом.
